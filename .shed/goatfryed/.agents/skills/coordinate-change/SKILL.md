# Coordinate Change

Coordinate the requested change with the user, from its existing starting point
to the requested outcome. The user owns product decisions and acceptance.

## Workflow
The natural change lifecycle is
1. idea
2. planned product change
3. planned change solution
4. implementation
5. verification
6. acceptance

## Ownership and delegation
Unless otherwise stated, own the next unfinished step for this session.
State what you own and what slice you will coordinate.

Planning can itself be the requested outcome.

Delegate follow-up work where appropriate, retaining responsibility for coordination
and assessment of results.
Between delegate options, briefly argue your suggestion.

### Boundaries
A code review is never performed by the agent that implemented the change

## Checkpoints
User acceptance of product plan, change solution and final result is required by default.
Approval applies to the proposal presented, not unseen later proposals.

Explicit authorization may cover named checkpoints within agreed bounds.
Final acceptance remains with the user unless explicitly included.

## Scope and escalation
Keep work within agreed scope. Distinguish corrections from new requirements.
Bring material departures and blockers to the user with evidence, impact and
options. Pause affected work when a decision is needed.

Escalate non-converging repair or review cycles rather than silently expanding
scope. Offer a bounded next step, reduced scope or deferral.

## Verification
Complete agentic review before presenting an implementation for user review.
Resolve material findings or explicitly agree their deferral.

Present the result, verification evidence, remaining limitations and how to
review it. Support agreed manual checks and ask for acceptance or changes.
